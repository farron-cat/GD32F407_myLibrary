## 0. 阅读前必读（三条前提）

### 0.1 引脚编号：**1~80 是模块排针编号，不是 LQFP100 物理脚号**

天空星核心板通过 **两排 2x20（共 80）排针** 连接；原理图/PCB 上的 `U9` 焊盘号
`1~80` 就是这套排针编号。例如：

- 模块 **pad 60 = PB9**（对应 LQFP100 的 PB9 = 物理脚 60，纯属巧合）
- 模块 **pad 63 = PB6**（LQFP100 物理脚为 92）

**做硬件对照时必须用本文档的「模块 pad 号」，不要用 LQFP100 数据手册脚号。**

### 0.2 原理图与 PCB **不同步**（重要）

实测发现两处不一致：

| 网络 | 原理图 | PCB |
|---|---|---|
| `CAN_TX` | 仅连 `TJA1050模块.TX`，**未连 MCU** | 已连 `U9.25` + `TJA1050-1.2` |
| `CAN_RX` | 仅连 `TJA1050模块.RX`，**未连 MCU** | 已连 `U9.26` + `TJA1050-1.3` |
| I2C | 原理图网络名为 `SCL` / `SDA` | PCB 网络名为 `PB6` / `PB7` |

> **结论：本文档全部以 PCB 焊盘级网表为准（PCB 更新更完整）。**
> 建议后续把原理图与 PCB 做一次完整同步（`设计 → 从 PCB 更新原理图` 或反向），
> 否则下次看原理图仍会得出错误结论。

### 0.3 读取方法（可复现）

本环境 `sch_Net.*` 系列接口返回空、`sch_Netlist.getNetlist()` 会超时，因此改用：

```js
// 1) 取本项目全部板卡（含 sch/pcb 的 UUID）
await eda.dmt_Project.getCurrentProjectInfo();
// 2) 切到目标 PCB
await eda.dmt_EditorControl.openDocument('<pcbUuid>');
// 3) 逐个元件取 位号 + 型号 + 封装 + 焊盘网络 —— 权威网表
await eda.pcb_PrimitiveComponent.getAllPrimitiveId();
await eda.pcb_PrimitiveComponent.get('<id>');            // 含 pads[].net
await eda.pcb_PrimitiveComponent.getAllPinsByPrimitiveId('<id>');
```

原理图侧可用 `eda.sch_PrimitiveComponent.getAllPrimitiveId()/get()/getAllPinsByPrimitiveId()`
与 `eda.sch_PrimitiveWire.getAll()`（导线自带 `net` 属性），但**注意：导线几何交叉处
不能用并查集判连通，会把不相干的网络误并**（实测把 `KCOL_1/2/3` 与 `KROW_1/2/3` 并成一张网）。

### 2.3 板上未引出 / 不可用的引脚

模块 **只引出 80 个引脚**，以下 GD32F407VET6 引脚**在排针上不存在**，
被核心板自身占用（USB、SWD 调试口等）：

```
PA9, PA10   ← 板载 CH340 USB-TTL 串口（USART0）
PA11, PA12  ← USB DM/DP
PA13, PA14  ← SWDIO / SWCLK
PB2, PB3    ← BOOT1 / JTDO
PC14, PC15  ← 32.768kHz 晶振脚（核心板上未装此晶振）
其余未列出的端口
```

> **对代码的意义**：使用 `USART0 + PA9/PA10 + printf 重定向` 是**正确**的——
> 它就是板载 USB-TTL 调试串口。但这**不是**排针上的可用引脚。

## 4. 功能模块电路详解

### 4.1 LED 阵列（8 颗 + 总开关）

```
        VCC ── Q1(S8550 PNP) ──┬── LED1.2 ─ LED1.1 ─ R15 ─ PD8   (pad30)
        (发射极)    集电极      ├── LED2.2 ─ LED2.1 ─ R16 ─ PD9   (pad29)
                                 ├── ...                        ...
        PC6 ── R9 ─ Q1 基极      └── LED8.2 ─ LED8.1 ─ R22 ─ PD15 (pad35)
        VCC ── R10 ─ Q1 基极（上拉）
```

- **`PC6 (LED_SW)` 低电平 → Q1 导通 → 给 8 颗 LED 阳极供电**（总开关，代码注释「低电平开」正确）
- **`PD8~PD15` 低电平 → 对应 LED 点亮**（灌电流，**低有效**）
- `PD8→LED1, PD9→LED2, PD10→LED3, PD11→LED4, PD12→LED5, PD13→LED6, PD14→LED7, PD15→LED8`

> 注意：8 颗 LED 的阳极电流全部经 `Q1` 一路通过，全亮时约 8×20mA ≈ 160mA，注意 Q1 余量。

### 4.2 独立按键（4 个）

```
PC0 ── SW17.3/.4 ─ SW17.1/.2 ── R11 ── GND     → KEY1

PC2 ── SW19    ── R13 ── GND                   → KEY3
PC3 ── SW20    ── R14 ── GND                   → KEY4
```

- 按下 → 引脚经串阻接地 → **输入 + 内部上拉 + 检低** 可用（与代码一致）
- `SW17~SW20` 与矩阵 `SW1~SW16` 是**独立**的两组，互不共用行/列（`SW17~20` 另一侧走 `$1N4296~$1N4299` → `R11~R14` → GND）

### 4.6 I2C 总线（PB6 / PB7）

| 按键 | `PC0~PC3` 输入 + 内部上拉 | `KEY1~KEY4` → `SW17~20` → `R11~R14` → GND | ✅ 正确 |
| 软件 I2C 引脚 | `PB6=SCL`, `PB7=SDA` | I2C 总线就在 PB6/PB7 | ✅ 正确 |
| 软件 I2C 电气 | `GPIO_OTYPE_OD` + `GPIO_PUPD_NONE` | **板上 R7/R8 已有外部上拉** | ✅ 正确 |

### 5.2 🔴 发现的问题（建议处理）

#### P1 — `PB10` 被代码当作 `USART2_TX`，硬件上是 **LCD 背光**

| 位置 | 内容 |
|---|---|
| 代码 | `Hardware/msp_uart/msp_uart.c:27-48` 中 `husart2`：`tx_port=GPIOB, tx_pin=GPIO_PIN_10, tx_af=GPIO_AF_7`；由 `msp_uart_init()` 执行 |
| 硬件 | `U9.pad23 (PB10) → 网络 LCD_BLK → CN20.7 + U10.7`（LCD 背光脚） |

**后果**：`msp_uart_init()` 一执行，PB10 即被配为 AF7 推挽输出，串口空闲高电平会
**持续驱动 LCD 背光网络**，导致背光常亮/常灭或随串口数据闪动。

**处理建议**：
1. 若不需要 USART2 → 从 `msp_uart_init()` 里去掉 `husart2`；
2. 若需要 USART2 → 注意 **GD32F407 的 `USART2_TX` 只能落在 `PA2 / PD5 / PB10 / PC10` 等固定复用脚**，
   而这三个备选脚在这块板上也各有用途（`PA2`=SPI-OLED、`PD5`=排针、`PC10`=排针），
   **因此基本需要改硬件**（把 LCD_BLK 换到别的脚），或干脆不用 USART2。

#### P2 — `PC3` 同时是 `KEY4` 与 `EXTI3`

| 位置 | 内容 |
|---|---|
| 代码 | `Hardware/msp_exti/msp_exti.h:9` `#define USE_EXTI3 1`，`EXTI3_PIN = GPIO_PIN_3`；同时 `Driver/bsp_keys/bsp_keys.c:8` 把 `PC3` 当 `KEY4` |
| 硬件 | `U9.pad57 (PC3) → KEY4 → SW20 → R14 → GND`（**只有一个物理按键**） |

**后果**：`msp_exti_init()` 先配 PC3=EXTI3，随后 `bsp_keys_config()` 又把它重配为输入；
EXTI 线由 SYSCFG 决定，**不会被关掉** → 按 KEY4 会**同时**产生 EXTI3 中断与 key 事件。

**处理建议**：若非有意（KEY4 兼唤醒键），改为 `#define USE_EXTI3 0`；若有意，请补注释说明。

#### P3 — `EXTI0` 的 `PA0` 在板上无上下拉

| 位置 | 内容 |
|---|---|
| 代码 | `msp_exti.h`：`EXTI0_PUPD = GPIO_PUPD_NONE`，`EXTI0_TRIG_TYPE = EXTI_TRIG_BOTH` |
| 硬件 | `U9.pad3 (PA0) → P3.3`，除排针外**无任何器件、无上下拉** |

**后果**：浮空输入 + 双边沿触发 → 极易受干扰产生大量伪中断。

**处理建议**：改为 `GPIO_PUPD_PULLUP`（或 PULLDOWN），或确认 `P3.3` 一定有外部信号驱动。

### 5.3 🟡 提示项（不是错误，但需知悉）

| 项 | 说明 |
|---|---|
| `PB11` 作 `USART2_RX` | 硬件上 PB11 只引到排针 `P3.24`，**板上无任何外设** → USART2 无法真正接收外部数据 |
| 内部 RTC 与 PCF8563 并存 | 代码 `msp_rtc_init(HXTAL)` 用 **MCU 内部 RTC**；`main.c:186` 又写 **PCF8563**。板上确有 PCF8563（带纽扣电池备电），建议明确分工或二选一；且 `msp_rtc_config()` 每次都 `rcu_bkp_reset_enable()`，**复位后内部 RTC 时间必丢** |
| `msp_uart.c:186` 越界风险 | `huart->recv_buff[huart->recv_length] = value;` 无上限检查，长包会越界写（与硬件无关，建议一并修复） |
| `PD5` / `PC10` 等空闲脚 | 已引到排针，可安全用于后续扩展 |
| `PB4` / `PD7` | 除排针外还挂在触摸屏 / LCD 排线上，若要做普通 GPIO 需确认不冲突 |
