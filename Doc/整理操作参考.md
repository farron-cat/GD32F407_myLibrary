## 0. 背景与依据

### 0.1 为什么 main.c 需要整理

`main.c` 是工程的起点，也是历史上**每个功能的第一个落脚点**。按仓库学习笔记 `note/README.md` 的总结，
本项目几乎所有模块都走过同一路径：

```
裸写在 main.c  →  抽成 bsp_*/msp_*  →  参数化 / 句柄化 / 宏开关
```

于是 `main.c` 逐次提交后不断累积：外设寄存器配置、器件自测函数、界面逻辑、全局变量、被注释掉的试验代码……
最终 453 行里，真正属于「程序入口」的只有一小部分。

### 0.2 规范依据（本工程自带）

来自 `模板结构.txt`：

| 目录 | 职责 |
|---|---|
| `App` | 应用层（界面、业务流程、回调） |
| `Middleware` | 中间件（当前为空，预留） |
| `Driver` | **片外**外设驱动（`bsp_*`，如 flash/OLED/PCF8563/NTC） |
| `Firmware` | ARM 内核文件、片内外设标准库 |
| `Hardware` | **片上**外设驱动（`msp_*`，如 uart/exti/rtc/iic/spi/adc/dma/看门狗） |
| `Project` | 工程文件 |
| `User` | 程序入口（`main.c` / `gd32f4xx_it.c` / `systick.c`） |

来自 `README.md`「开发注意事项」的两条硬约束：

1. **引脚与时钟配置统一放 `Hardware/msp_*.c`，不要散落在业务代码中。**
2. **新增硬件驱动写在 `Driver/bsp_*.c`，不要直接在 `main.c` 里操作寄存器。**
3. 中断服务函数里尽量只做标志位处理，耗时逻辑放到主循环。

> 对照之下，当前 `main.c` 同时违反了 1、2 两条：里面直接写着 DMA/ADC 的寄存器级配置。

### 0.3 整理原则

- **一次一块**：按第 3 节顺序执行，每块做完编译一次。
- **先删冲突、再迁移**：见 3.1（ADC 与 `msp_adc.c` 存在**同名符号冲突**，必须先处理）。
- **main.c 只保留入口编排**：系统时钟 → 外设初始化调用 → 应用初始化 → 主循环。
- **不改变功能行为**：本轮目标是「搬位置」，不是「改逻辑」。

### 1.1 两个必须优先处理的隐患

1. **符号冲突（高优先级）**
   - `main.c` 的 `msp_adc_get(void)` 与 `Hardware/msp_adc/msp_adc.c` 的 `msp_adc_get(uint8_t)` **函数名相同**。
   - C 不支持重载，两者一旦同时参与编译，链接阶段会报重复符号（或某一方被静默覆盖）。
   - **结论：必须先删除 `main.c` 中的旧 ADC 实现（L162–275），再启用 `msp_adc.c`。**

2. **DMA1_CH0 资源争用（高优先级）**
   - ADC 的搬运使用 `DMA1_CH0` + `SUBPERI0`，**循环模式**、无中断（见 `msp_adc.c`）。
   - `DMA_m2m_config()` 同样使用 `DMA1_CH0`，**内存到内存 + 传输完成中断**。
   - 二者配置互斥，不可能同时生效。这也是 DMA M2M 必须被隔离（独立模块或删除）的硬件理由。

## 2. 分层归属速查

整理任何一块代码前，先用下面的判定树定归属：

```
这段代码在做什么？
├─ 操作寄存器 / 配引脚 / 开时钟 / 配 DMA / 配中断向量     → Hardware/msp_xxx/（片上）
├─ 遵守某颗片外芯片的时序或协议（读 ID、擦写、显存刷新）   → Driver/bsp_xxx/（片外）
├─ 界面怎么画、页面怎么切、人机交互流程                  → App/（应用层）
├─ 只是把上面几层「初始化调用」串起来 + 主循环            → User/main.c
└─ 供上电后自动跑的中断处理骨架                          → User/gd32f4xx_it.c
```

**对照表**

| main.c 里常见的东西 | 该去哪 | 本工程已有先例 |
|---|---|---|
| `xxx_config()` / `xxx_init()` 里的寄存器操作 | `Hardware/msp_*` | `msp_uart` `msp_exti` `msp_rtc` `msp_iic` `msp_spi` |
| 外设中断服务函数（如 DMA/USART 通道中断） | `Hardware/msp_*` 内 | `msp_uart.c` 里的 `USART0_IRQHandler` |
| 器件读写（flash/OLED/RTC 芯片） | `Driver/bsp_*` | `bsp_flash` `bsp_iic_oled` `bsp_pcf8563` |
| 屏幕显示内容、页面刷新 | `App/` | 待建 `App/app_ui` |
| 弱符号回调的业务实现 | `App/` | 待建 `App/app_uart` |
| 器件/外设综合自测 | `App/` | 待建 `App/app_test` |
| 全局的「跨函数暂存」变量 | 尽量局部化；必须全局则收敛到对应模块 |

**main.c 里禁止出现（反面清单）**

- ❌ `rcu_periph_clock_enable(...)`、`gpio_mode_set(...)`、`dma_..._config(...)`、`adc_...(...)` 等寄存器/外设调用；
- ❌ `DMAx_Channely_IRQHandler` 之类的**非系统**中断服务函数（USART/DMA 等通道中断应随其驱动）；
- ❌ 全局的收发/搬运缓冲区（如 `dat[1024]`、`adc_results[]`）；
- ❌ 器件自测的长函数（`oled_test`、`flash_test`）；
- ❌ 大段被注释掉的「历史试验代码」。

> 例外：`User/gd32f4xx_it.c` 中的 `SysTick_Handler` 属于系统级中断，保留在 `User/`，
> 但其内部只应做「标志位/时间递减」这类轻量动作（当前它调用了 `bsp_188_leds_scan()`，可接受）。

## 3. 逐块整理操作

每块统一给出：**现状 → 目标 → 操作步骤 → 依赖与冲突 → git 依据 → 验证方法**。
**执行顺序即推荐顺序**（3.1 必须最先做）。

### 3.1 ADC（旧实现删除 → 改用 `Hardware/msp_adc`）★最先做

**现状**

- `main.c` L162 `adc_results[2]`、L163–195 `msp_adc_dma_config()`、L197–252 `msp_adc_config()`、L254–275 `msp_adc_get(void)`。
- 旧版仅配置 **2 个通道**：电位器（`ADC_CHANNEL_14` / PC4）、内部温度（`ADC_CHANNEL_16`）。
- 同时 `Hardware/msp_adc/msp_adc.c` 已存在（当前未提交），提供 `msp_adc_init()` 与 `msp_adc_get(uint8_t i)`，且升级为 **3 通道**：

| 索引 | 通道 | 引脚 / 用途 | 对应宏 |
|---|---|---|---|
| `encodes[0]` | `ADC_CHANNEL_14` | **PC4 电位器** | `msp_adc_get(0)` |
| `encodes[1]` | `ADC_CHANNEL_16` | **内部温度传感器** | `msp_adc_get(1)` |
| `encodes[2]` | `ADC_CHANNEL_1` | **PA1 NTC 热敏电阻** | `NTC_GET_ENCODE()`（见 3.3） |

**目标**

- 删除 `main.c` 中 L162–275 的**全部旧 ADC 代码**（消除与 `msp_adc.c` 的同名符号冲突）。
- `main()` 中把 `msp_adc_dma_config();` + `msp_adc_config();` 两行**合并为一个** `msp_adc_init();`。
- 主循环中 `msp_adc_get();`（旧无参）改为按通道取值；电压/温度换算与 `printf` 属**应用层**，移到 `App/`（或临时放到 main 但需注明）。

**操作步骤**

1. 删除 L162–275（`adc_results` / `msp_adc_dma_config` / `msp_adc_config` / `msp_adc_get`）。
2. `main()` 初始化段：
   ```c
   // 原：msp_adc_dma_config();  // 旧 DMA
   //     msp_adc_config();      // 旧 ADC（含内部温度）
   msp_adc_init();               // 新：DMA + ADC 一并初始化（3 通道）
   ```
3. 主循环中原本调用 `msp_adc_get()` 的地方去掉或改为读取指定通道：
   ```c
   uint16_t pot  = msp_adc_get(0);   // 电位器
   uint16_t temp = msp_adc_get(1);   // 内部温度（原始码值）
   // 换算 / 打印若仍需，放到 App 层函数中
   ```
4. 若需要保留「电位器电压 + 内部温度」的调试打印，新建 `App/app_test` 或 `App/app_ui` 中一个函数承载（见 3.6/3.7），**不要**再写回 main。
5. 在 `msp_adc.h` 中确认 `ADC_LEN = 3`、`VREF = 3.3`，且 `msp_adc_get()` 的入参是**通道索引**而非通道号。

**依赖与冲突**

- 与 `msp_adc.c` 的**同名函数**：必须先删后启，否则链接失败。
- 与 DMA M2M 共用 `DMA1_CH0`：删掉 ADC 旧实现后，`DMA1_CH0` 由 `msp_adc.c` 独占（循环搬运）。
- 内部温度公式：`(1.45 - V) * 1000 / 4.1 + 25`（V 为电压）；温度通道采样时间需满足手册 `tS_temp = 17.1us`（见 `note/19-ADC.md`）。

**git 依据**：`b80ce12`（ADC 测试·芯片温度）→ `d502d82`（扫描模式 + 每通道 EOC）→ `f8b4b85`（多通道 + DMA 搬运）。

**验证**：编译通过（无重复符号）；串口打印电位器电压随旋钮变化；内部温度在室温附近合理；NTC 通路待 3.3 完成后验证。

### 3.2 独立/窗口看门狗（已完成范例，记录归档）

**现状**

- 工作区未提交的改动已把 `msp_fwdgt_config()`、`msp_wwdgt_config()` **从 `main.c` 删除**。
- 新模块 `Hardware/msp_fwdgt/`、`Hardware/msp_wwdgt/` 已建立（当前未提交）。

**目标（已完成）**：两个初始化函数落在 `Hardware/`，`main.c` 只保留（注释的）调用入口。

**操作步骤（参考：本次即按此做的）**

1. 新建 `Hardware/msp_fwdgt/msp_fwdgt.{c,h}`，把函数体原样搬入，头文件声明 `void msp_fwdgt_config(void);`。
2. 新建 `Hardware/msp_wwdgt/msp_wwdgt.{c,h}`，同上。
3. `main.c` 顶部删除函数定义，改为 `#include "msp_fwdgt.h"` / `#include "msp_wwdgt.h"`，调用处保留在 `main()` 末尾附近（**看门狗使能要放在初始化之后**，见下方坑）。
4. 在 `main()` 主循环中喂狗：独立看门狗 `fwdgt_counter_reload();`；窗口看门狗 `wwdgt_counter_update(0x7F);`。

**依赖与冲突 / 注意**

- `msp_fwdgt` 使用 `IRC32K`（代码里先关后开再等稳定），超时值 `100`（32 kHz/32 → 计数 1 kHz → 100 ms）。
- `msp_wwdgt` 用 `PCLK1 = 42 MHz`，`wwdgt_config(0x7F, 0x50, DIV1)` → 窗口约 **4.58 ~ 6.24 ms**，喂狗周期必须落在这个窗口内（本工程用 5 ms 级别）。
- **使能位置**：`bbce6b7` 提交才把使能挪到 `main()` 末尾——因为前面的初始化会消耗时间，过早使能可能还没进主循环就被复位。这是历史「翻车点」，务必保留注释。

**git 依据**：`6827512`（独立看门狗）→ `bbce6b7`（窗口看门狗 / 修正使能时机）。

**验证**：使能看门狗后程序若进入死循环（不喂狗）应复位；正常运行不复位。

### 3.3 NTC 热敏电阻（`Driver/bsp_ntc`）

**现状**

- `Driver/bsp_ntc/bsp_ntc.{c,h}` 已建立（当前未提交），提供 `bsp_ntc_init()`、`bsp_ntc_get_tem()`。
- 通过 `#define NTC_GET_ENCODE() msp_adc_get(2)` 复用 ADC 的**第 3 通道**（PA1）。
- 内部实现：ADC 码值 → 电压 → 电阻（10k 分压）→ 查表（`temp_table[]`，-55 ~ +125 ℃）得温度。
- 当前 `main.c` **尚未调用**这两个接口。

**目标**

- `main()` 初始化段新增 `bsp_ntc_init();`。
- 需要显示/上报温度时，主循环调用 `bsp_ntc_get_tem()`。

**操作步骤**

1. `main.c` 增加 `#include "bsp_ntc.h"`。
2. 初始化段（`bsp_*` 组）追加：`bsp_ntc_init();`。
3. 主循环中按需使用：
   ```c
   int8_t tem = bsp_ntc_get_tem();   // 摄氏度
   ```

**依赖与冲突**

- **强依赖 3.1**：必须先把 ADC 换成 `msp_adc_init()`（3 通道），`encodes[2]` 才有 PA1 的采样值。
- 引脚：PA1 = `ADC_CHANNEL_1`（`msp_adc.c` 中 `adc_routine_channel_config(ADC0, 2, ADC_CHANNEL_1, ...)`）。
- `bsp_ntc.c` 里 `search_tem()` 使用 `abs()`，头文件需保证 `<stdlib.h>` 可用（若报隐式声明，补 include）。

**git 依据**：对本仓库而言是**新增功能**（`bsp_ntc/`、`msp_adc` 支持 PA1 均为未提交改动）；硬件依据见 `Doc/硬件信息汇总.md`（`NTC SDNT2012X103` 接 **PA1**）。

**验证**：串口/OLED 打印 NTC 温度；用手捏热敏电阻温度应上升。

### 3.4 DMA M2M（内存到内存试验：二选一）

**现状**

- `main.c` L24 `uint8_t dat[1024]`、L41–72 `DMA_m2m_config()`、L74–86 `DMA1_Channel0_IRQHandler()`。
- 用途是「学 DMA」：内存→内存搬运、传输完成中断里打印、动态配置搬运地址/长度。

**目标（两种方案任选其一）**

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 封装成模块** | 新建 `Hardware/msp_dma/msp_dma.{c,h}`，把 `DMA_m2m_config()`（改名为 `msp_dma_m2m_config(...)`）与中断服务函数搬进去，`dat[]` 也一并移入（改为模块内静态） | 想把 DMA M2M 当「可复用能力」保留 |
| **B. 直接删除**（推荐） | 删除 L24、L41–86 及其在 `main()` 中已注释的调用 | 已由 `msp_adc` 演示 DMA 用法，M2M 不再是主线的必需功能 |

**操作步骤（方案 A 为例）**

1. 新建 `Hardware/msp_dma/`，迁移 `DMA_m2m_config`（含 `dat[]`）；中断服务函数随文件走。
2. `main.c` 顶部 `#include "msp_dma.h"`，删除原定义。
3. `main()` 里保持**注释状态**（如原 L349 `// DMA_m2m_config();`），避免与 ADC 抢 `DMA1_CH0`。

**依赖与冲突（关键）**

- **与 ADC 冲突**：两者都要用 `DMA1_CH0`。ADC 走 `SUBPERI0` + 循环模式 + 无中断；M2M 走 M2M 方向 + 中断。**不能同时使能**。
- 若方案 A 保留，则**必须**加编译开关或运行期二选一，并在注释里写明「与 ADC 互斥」。

**git 依据**：`0c40272`（DMA m2m 测试）→ `86263f2`（使用中断输出结果）→ `3085f3a`（动态配置 DMA 参数）。

**验证**：方案 B 则确认删除后编译、烧录、ADC 仍正常；方案 A 则单独使能 M2M 时串口能打印出搬运后的内容。

### 3.5 串口接收回调 `on_usart_recv`（→ `App/app_uart`）

**现状**

- `main.c` L26–39 定义了 `on_usart_recv(USART_HandleTypeDef *huart)`。
- `Hardware/msp_uart/msp_uart.c` 中以 `__weak void on_usart_recv(...)` 提供**默认实现**（原样回显），main.c 的重定义会**覆盖**这个弱符号。

**机制说明（先理解再搬）**

```
uart_irq_handle()  ——收到一包（IDLE 中断）——> on_usart_recv(huart)
                                                   │
                          ┌────────────────────────┴────────────────────────┐
                          │ 默认（__weak，在 msp_uart.c）：原样 send_string │
                          │ 覆盖（非 weak，可在任意 .c）：业务处理          │
                          └─────────────────────────────────────────────────┘
```

- 回调的**声明**在 `msp_uart.h`（`extern void on_usart_recv(...)`），**弱实现**在 `msp_uart.c`。
- 只要工程里存在一个非 weak 的 `on_usart_recv`，链接即选择它，无需改 `msp_uart.c`。

**目标**：把 main.c 中的实现搬到 `App/app_uart.c`，main.c 不再出现该函数。

**操作步骤**

1. 新建 `App/app_uart/app_uart.{c,h}`。
2. `#include "msp_uart.h"` 与 `<stdio.h>`，把 L26–39 函数体原样移入 `app_uart.c`。
3. `app_uart.h` 中声明 `void app_uart_init(void);`（**不要**再声明 `on_usart_recv`，它由 `msp_uart.h` 管）。
4. `main.c` 删除该函数，保留 `#include "msp_uart.h"`（`msp_uart_init()` 仍要在 main 调用）。
5. 若应用层需要初始化动作（如清缓冲），在 `app_uart_init()` 里做，并在 `main()` 中调用。

**依赖与冲突（重要）**

- main.c 现版本的回调里对 `USART0` 分支调用了 **`dma_periph_address_config(DMA1, DMA_CH0, ...)` 重装 DMA**——
  这同样占用 `DMA1_CH0`，**与 ADC（3.1）/ DMA M2M（3.4）冲突**。
  迁移时应一并决定：若当前串口用的是「中断收（RBNE+IDLE）」而非 DMA，这段重装逻辑属于早期试验，建议**去掉**；
  若确实要用 USART0 DMA 接收，则需为其分配**另一个 DMA 通道**（不能与 ADC 共用）。
- 回显默认实现已经在 `msp_uart.c`，删除 main.c 覆盖后行为会回到「原样回显」。

**git 依据**：`31f8243` `d41b189` `ebc8568` `8e13d14` `56609c3` `6a37639`（UART 句柄化过程）→ `d251346`（usart 分支合并）。详见 `note/04-串口USART.md`。

**验证**：串口助手发送数据，能收到业务处理后的结果（或默认回显）。

## 4. main() 目标骨架

整理后 `main.c` 只承担「入口编排 + 主循环」。下面是目标形态（**保持原功能与节拍不变**，仅调整组织方式）：

```c
#include "main.h"
#include "gd32f4xx.h"
#include "systick.h"
#include <stdio.h>

#include "msp_exti.h"
#include "msp_rtc.h"
#include "msp_iic.h"
#include "msp_spi.h"
#include "msp_adc.h"        /* 替代原 msp_adc_dma_config / msp_adc_config */

/* ================= 片外器件（Driver） ================= */
#include "bsp_leds.h"
#include "bsp_keys.h"
#include "bsp_buzzer.h"
#include "bsp_iic_oled.h"
#include "bsp_spi_oled.h"
#include "bsp_pcf8563.h"
#include "bsp_flash.h"
#include "bsp_188_leds.h"
#include "bsp_ntc.h"

/* ================= 应用层（App） ================= */
#include "app_ui.h"
// #include "app_test.h"        /* 需要跑器件自测时打开 */

int main(void)
{
    /* ---------- 1. 系统基础（保留在 main） ---------- */
    nvic_priority_group_set(NVIC_PRIGROUP_PRE2_SUB2);
    rcu_timer_clock_prescaler_config(RCU_TIMER_PSC_MUL4);
    systick_config();

    /* ---------- 2. 片内外设（Hardware） ---------- */
    msp_uart_init();
    msp_exti_init();
    msp_rtc_init(HXTAL);
    msp_iic_init();
    msp_adc_init();          /* 合并原两行：ADC + DMA（3 通道） */
    msp_spi_init();

    /* ---------- 3. 片外器件（Driver） ---------- */
    bsp_leds_config();
    bsp_keys_config();
    bsp_buzzer_init();
    bsp_iic_oled_init();
    bsp_spi_oled_init();
    bsp_pcf8563_init();
    bsp_flash_init();
    bsp_188_leds_init();
    bsp_ntc_init();

    /* ---------- 4. 应用层初始化 ---------- */
    app_ui_init();           /* 首屏（贴 BMP1 等） */
    // app_test_flash();     /* 需要时不定期手动跑自测 */

    /* ---------- 5. 看门狗最后使能（前面初始化会耗时） ---------- */
    // msp_fwdgt_config();
    // msp_wwdgt_config();

    printf("============ start ============\r\n");
    printf("SystemCoreClock = %u\r\n", (unsigned int)SystemCoreClock);

    /* ---------- 6. 主循环 ---------- */
    Time_pcf time;
    uint32_t num = 0;

    for (;;)
    {
        /* 188 数码管：显示上电秒数（0~199） */
        num = get_us_cnt() / 1000000 % 200;
        bsp_188_leds_set_num((uint8_t)num);

        /* RTC 读取 → 应用层刷新界面 */
        bsp_pcf8563_read_time(&time);
        app_ui_show_rtc(&time);

        /* 调试打印（若想更干净，可移入 App 层） */
        printf("20%02d-%02d-%02d %02d:%02d:%02d Week:%d\r\n",
               time.year % 100, time.month, time.day,
               time.hour, time.minutes, time.second, time.week);

        /* 看门狗喂狗（若启用） */
        // wwdgt_counter_update(0x7F);
    }
}
```
